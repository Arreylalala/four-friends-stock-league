# 华尔街之狼 · 股票战报

网站：https://arreylalala.github.io/four-friends-stock-league/

## 项目介绍

为伦、镭、健、超四位朋友提供每日投资战报。每日录入股票与基金盈亏，网页自动合计、排名并生成走势；支持周、月、年、统计以来，以及全员／单人视角和当前连胜展示。

累计盈亏采用独立的账户校准起点，自动叠加之后的已结算每日盈亏，不随周期切换清零。数据需要手动填写 JSON，更新提交后由 GitHub Actions 构建并发布到 GitHub Pages；不自动从证券账户采集数据。

## 数据文件与每日更新

- `data/config.json`：收益率开关与开始日期。
- `data/daily/YYYY-MM.json`：每月每日盈亏数组；最新日期放在最上面。跨月时在 GitHub 新建对应月份文件即可，不需要登记文件清单，程序自动发现并按日期汇总。历史月份无需改动，必要时仍可更正。
- `data/cumulative-adjustments.json`：独立的累计盈亏校准数组；最新校准放在最上面。没有起点的人显示“待录入”，不会用每日记录合计替代真实账户累计值。

编辑后提交到 `main`，自动测试、构建、发布。`public/scoreboard.json` 是自动汇总的网页读取文件，请勿手工编辑；原根目录 `scoreboard.json` 已迁移，不再维护。不要上传 `site.zip`。

### 新建一个月或新增一天

例如 `data/daily/2026-10.json`（仅为格式示例，不是实际战报）：

```json
[
  {
    "date": "2026-10-01",
    "amounts": {
      "lun": { "stock": 100, "fund": -30 },
      "lei": { "stock": 0, "fund": 0 },
      "jian": { "stock": null, "fund": null },
      "chao": { "stock": -20, "fund": 5 }
    }
  }
]
```

新增一天时，在数组最上方增加对象，与下一条之间用逗号分隔。金额单位为元；无持仓或无盈亏填 `0`，未出结果填 `null`，stock 和 fund 两项必填。任一分项为 null 时该人待结算；四人的分项全为数字才结算该日。日期必须有效、不重复，并属于文件名月份。

页面金额、排名、走势、胜负与连胜仍按股票加基金的合计计算，不展示分项。跨月、跨年统计与连胜连续计算。可选的 returns 仍使用百分数（1.25 表示 1.25%）。

### 首次录入或以后校准累计盈亏

编辑 `data/cumulative-adjustments.json`，以文件中的最新内容为准。首次设置时填写真实日期和金额；如果仍为占位模板，可直接替换模板。已录入真实校准后，后续校准新增记录并保留历史。0 是参与计算的有效数值，不表示“未知”。以下仅为结构示例，不代表当前账户数据：

```json
[
  {
    "date": "2026-09-22",
    "amounts": {
      "lun": -2000,
      "lei": 1500,
      "jian": -800,
      "chao": 300
    }
  }
]
```

- 金额是截至该日期结束时的股票＋基金累计盈亏，单位元；盈利为正、亏损为负，0 为持平。
- 每人取自己的最新校准值，仅累加校准次日起的已结算每日盈亏；不重复加校准当天，不受页面月／周／年筛选影响。
- 再次校准时，在数组最上方新增记录并保留历史；可只填写一个人。同一天的校准放在同一条记录中，日期不可重复。省略成员表示该人不校准，不能用 null 代替。
- 改动校准日期之前（含当天）的每日记录，不影响该起点之后的累计；改动之后的记录会自动重算。未结算天数会标注为暂未计入。
- 校准只影响累计区，不改变每日战报、排行榜、胜负或连胜。校准日期不要求已有每日战报。
- 历史上曾提供 2026-09-23 四人均为 0 的初始模板；不要用文档示例覆盖已经填写的真实校准。

## 本地开发

需要 Node.js 24 和 pnpm 11.19.0。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

每次启动开发服务会汇总 data 目录数据；服务运行期间修改数据后，运行 `node scripts/prepare-data.mjs` 并刷新页面。

## 验证与发布

```sh
git pull --ff-only
pnpm check
git add <本次修改的文件>
git commit -m "Describe the change"
git push origin main
```

`pnpm check` 执行测试、生产构建、静态资源路径和数据一致性检查。Pull request 和迁移分支只构建验证，只有 main 部署。失败时不会替换当前网站。生产资源必须使用 `/four-friends-stock-league/` 子路径。

连胜徽章在两处均使用当前累计连胜，至少 2 场显示为 `2连胜`，不得改为历史最长连胜。
